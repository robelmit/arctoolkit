# Checkout pages

The two pages of the [checkout](../checkout), in React with [shadcn/ui](https://ui.shadcn.com):

- **Payment page** (`pay.html`): what the customer sees. The amount, a live countdown, the QR code, "Open in wallet", copy buttons, and the status until it turns into a receipt. On address-mode USDC invoices, a "From another chain" tab pays through Circle's CCTP with the customer's browser wallet.
- **Dashboard** (`dashboard.html`): what the shop sees after entering its API key. Chain status, open invoices, money received, payments to review, webhooks waiting, and "New invoice".

The checkout server serves the build: it reads `dist/` once at start and fills each page's data slot with JSON. Nothing here talks to any server but the checkout.

## Build

```
pnpm --filter @arctoolkit/checkout-web build     # → dist/
```

`pnpm build` at the repository root builds it too, before the checkout.

## How it is made

- **shadcn/ui, Nova preset**: Radix primitives, Tailwind CSS 4, DM Sans and DM Mono, [Phosphor](https://phosphoricons.com) icons. The components live in `src/components/ui`, generated by the shadcn CLI (`components.json`) and restyled to the toolkit look shared with soltoolkit and hoodtoolkit: a near-black page, cards with a solid bottom edge, raised green pill buttons and pill tabs. Dark only, so a page never flashes light.
- **Everything self-hosted**: fonts are bundled, nothing is inlined as a `data:` URI, and no script is written into the HTML. The server's content security policy allows scripts, styles, fonts and images from itself only.
- **Wallet flow without React** (`src/pay/wallet.ts`): connect, switch chain, check the balance, approve if needed, send. Tested on its own with a recorded-style wallet.
- **Phone first**: both pages were checked at 390 px wide and on a desktop.

To add a component: `pnpm dlx shadcn@latest add <name>` in this folder.

## Tests

```
pnpm --filter @arctoolkit/checkout-web test
```

6 tests: the wallet flow (the exact transactions asked for, a skipped approval, a short balance, a cancel, a failed approval) and the number and time formatting.
